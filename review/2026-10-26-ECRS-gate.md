# 能量＋ECRS 首轮验证结果

2026-10-26。结论：**实现内部一致性已得到初步验证；暂缓扩建大平台，保留小范围研究验证。** 当前结果支持修正可行性约束，但还不足以证明新仿真器具有足够大的研究增量。

## 已完成

- 恢复并逐文件核对 GitHub v0.2.0 源码，基线为 `7586e31095666d7c8e5cc59c7a88b47e73e5c058`。
- 核对 ERCOT 官方 NPRR1282 和现行第 6、9 节。ECRS 一小时持续要求可确认；完整 SCED 联合库存/功率公式及真实结算仍未完成逐项对照。
- 新增五分钟能量＋ECRS 实验环境，保留连续 SoC、过去信息截止、显式发布延迟、动作裁剪记录、oracle 与环境回放一致性。
- 环境采用保守的仅放电侧 reserve 模型，未实现充电削减提供上调、AS 实际部署、真实报价出清或日前 AS。五分钟 LMP×功率是现金流代理，不是真实 ERCOT 完整结算。
- 新增 20 项有针对性的测试；与原 151 项一起，171 项全部通过。213 条警告保留在测试输出中，没有把无警告作为完成条件。

原始项目数据位于云服务器，当前尚未取得。为测试接口与探索参数影响，读取了 HybridBid 固定提交 `68c1a62398e53ed4785c4dd67996ed547c4da34b` 的公开处理后价格文件；文件二进制 hash 与 GitHub blob 一致。没有通过补零或插值绕过缺口。

|---|---:|---:|---:|
| 2026-01 | 8,928 | 72 | 82 |

3 月 ECRS 列缺失率约 35.4%；这些文件不能直接填零后当成完整市场记录。原 HybridBid 的评价路径会把缺失价格填零，本次新 runner 拒绝这种处理。

两个实际评估面板及其前置历史均无空值或时间缺口。2 月面板先运行，随后运行 1 月压力面板；这是探索性顺序，不是预注册的独立验证。源文件的逐格处理历史和实际发布时间仍未核实。

统一设置：100 MW / 200 MWh，RTE 85%，退化成本 $2/MWh，面板起止 SoC 都为 50%，面板内不重置。MPC 用过去一天价格和一小时预测时域。价格可见性假设为区间结束再延迟五分钟；该延迟不是已验证的市场事实。

## 结果

0.25h 是对相关项目参数的敏感性检查，**不是历史 pre-RTC+B ECRS 规则**。所有因果策略均在同一个一小时环境中执行，不可交付的请求先裁剪再记收入。

| Central 运行窗口 | 0.25h 规划请求被裁剪 | 占全部时段 | 0.25h→1h oracle 收益下降 |
|---|---:|---:|---:|
| 2026-02-02 至 02-04 | 154 / 864 | 17.82% | 0.0233% |
| 2026-01-24 至 01-26 | 157 / 864 | 18.17% | 0.4081% |

Oracle 下降比例以 0.25h oracle 收益为分母。两个 oracle 均回放得到自身目标值、没有被环境裁剪，报告的 MIP gap 为 0。

| 策略净收益代理（USD） | 2 月面板 | 1 月压力面板 |
|---|---:|---:|
| 闲置 | 0.00 | 0.00 |
| 能量 MPC | 2,075.70 | -19,052.84 |
| 能量＋ECRS，一小时规划 | 2,137.36 | -17,854.10 |
| 0.25h 规划、在一小时环境裁剪执行 | 2,430.28 | -17,180.28 |
| 一小时 oracle | 24,425.11 | 212,942.57 |
| 0.25h oracle | 24,430.79 | 213,815.24 |

不能把结果解读为“一小时正确模型让策略收益更高”：这两个窗口内并非如此。错误持续时间的规划器经过合法裁剪后收益反而略高，两个版本在压力面板均亏损。它们采用的简单预测和短时域 MPC 不是强基线，现有差异不能隔离预测质量、短视规划和约束设定的作用。

## 对是否继续的判断

1. **软件正确性有明确价值。** 大约 18% 的时段暴露出 reserve 请求不可按此一小时模型执行，因此统一可行性校验和记录机制值得保留。
2. **经济影响证据目前偏弱。** 在这两个窗口和该保守模型中，持续时间修正只让总 oracle 收益下降 0.02% 至 0.41%。不能凭合成大反例或裁剪频率，推断整个市场收益比较会大幅改变。
3. **尚未证明完整规则一致性。** 一小时参数有官方依据，但“放电后保留完整 reserve 能量”等是保守建模选择，原型尚不能称为完整 RTC+B 仿真器。
4. **下一步保持窄范围。** 取得原始数据和时间戳含义后，核对精确联合库存约束，固定新留出窗口；再用较可靠的预测/优化基线检验不可交付承诺、收益和排名。如果这些仍未显示实质差异，应作为小工具或审计结果收尾，而不是继续加 AS、RL 或 LLM 来扩大项目。
