# RTCB-Gym — 规则可追溯的储能策略评测环境

更新：2026-10-26。工作目录：`/Users/aurorazhang/Desktop/Open Simulation Environment/`。

本蓝图取代原有按版本扩张的路线。当前任务是验证：**post-RTC+B 的决策规则和信息时间线，是否需要一套现有公开工具尚未充分覆盖的共同评测环境。** 在这个问题有证据之前，不自动推进到全产品、情景生成或 LLM agent。

## 1. 目标和唯一主线

为研究者提供一个单储能、价格接受者的实验环境：策略使用当时可见的信息提出决策，经过同一套可行性与执行模型，再由同一账本评价收益、约束违反和风险。

当前研究问题：

> 当储能的辅助服务持续时间、联合库存约束、报价/调度时点和价格可见性被明确建模后，常见简化会在多大程度上改变可执行决策、收益估计或方法排序？

候选贡献是**可核对的决策任务与统一评价协议**。是否形成独立 benchmark 或论文贡献，取决于规则核对、真实数据和对照实验；不能由功能数量或单元测试数量决定。

对外暂用定位：

> An open, auditable environment for evaluating battery-storage strategies under explicitly scoped post-RTC+B assumptions.

不再使用“第一个开放环境”“旧算法全部失效”“历史回放几乎没有 sim-to-real gap”。MPC、随机优化和 RL 仍可使用，需要核对的是它们的任务、信息集、约束和收益模型。

## 3. 数学任务先于接口扩张

设 t 为决策事件，e_t 为储能侧库存（MWh）。策略的信息集为：

```
I_t = {state, calendar, data records whose available_at <= decision_time_t}
(requested_energy_t, requested_reserve_t) = policy(I_t)
executed_t = execution_model(requested_t, state_t, verified_rules)
state_(t+1) = physical_model(state_t, executed_t, realized_activation_t)
reward_t = settlement_model(positions_t, executed_t, realized_prices_t)
```

每个实验必须明确五个时点：数据对应区间、信息发布时间、策略决策时间、执行有效区间、结算区间。SCED 执行时间不自动等于价格区间开始；区间结束也不自动等于价格已发布。

同一实验中的策略、oracle、执行裁剪和评价必须采用相同的物理参数、SoC 边界、收益定义和评估窗口。oracle 的特权信息单独标记。

## 4. 当前最小模型的范围

### 4.1 已实现的实验子集

- 单储能、外生价格、名义五分钟时间网格。
- 净能量功率 p_t，正值放电，负值充电；ECRS 容量 a_t >= 0。
- 储能效率、功率和 SoC 限制；连续面板内跨日传递 SoC。
- 为到达终端 SoC 保留可达性；不在每日零点免费重置库存。
- 保守限制：充电时不提供 ECRS；放电与 ECRS 共享功率上限；基础调度后保留完整持续时间的 reserve 能量。
- 无实际 AS 部署，容量预留不沿基础轨迹消耗库存。
- 五分钟 LMP/MCPC 收益代理；不混称为真实完整 ERCOT 结算。

当前可行域：

```
e_(t+1) = e_t + eta_c * c_t * dt - d_t * dt / eta_d
E_min <= e_(t+1) <= E_max
c_t <= P * (1 - u_t)
d_t + a_t <= P * u_t,                 u_t in {0, 1}
tau * a_t / eta_d <= e_(t+1) - E_min
e_T >= E * soc_terminal_min
```

dt=1/12 小时，eta_c=eta_d=sqrt(RTE)，p_t=d_t-c_t。tau=1 小时有官方规则依据；上面的联合库存时点与仅放电侧限制是**保守建模选择**，完整 SCED 等价性尚未确立。

收益代理为：

```
net_proxy = p_t * LMP_t * dt + a_t * ECRS_MCPC_t * dt
            - abs(p_t) * degradation_cost * dt
```

负价格下不得通过同时充放电燃烧能量获利。oracle 需显式保证互斥，并在同一环境回放达到其数值目标；浮点求解结果不表述为市场层面的定理。

### 4.2 仍需核实或另行建模

- SCED 对基础能量与 reserve 的精确联合库存约束和持续时间。
- 充电削减所提供的上调能力、资源资格、爬坡/响应要求。
- 不规则 SCED 执行区间与真实价格有效时间。
- ECRS 实际部署、部署能量对 SoC 的影响和持续履约。
- 真实报价、部分中标、调度信号与策略请求的区别。
- 15 分钟能量 SPP、AS 价格加权、日前头寸及偏差等实际结算过程。

不能在缺少部署数据时把生成情景当作实际部署；不能把多个五分钟 LMP 简单乘功率的现金流当作已核对的真实结算。

## 5. 相关工作与差异定位

以下审查固定于 2026-10-26 的提交快照，不能推广为所有现有工作的结论。

| 项目 | 已有内容 | 本次发现的边界 |
|---|---|---|
| `ercot-rtcb-bench` | 能量＋五类 AS、数据版本、确定性/随机优化/DFL、滚动回测 | Gym 是占位；部分 AS 库存约束未覆盖；负价格 LP 为松弛；目标日整日实际净负荷参与 analog 选择 |
| `HybridBid` | Gym、学习方法、专家轨迹、五类 AS、连续评价 | 训练与评价定义不同；部分持续时间参数与规则冲突；同期价格可见；独立样本外和当前入口复现仍有问题 |
| RTCB-Gym | 统一策略接口、能量物理/结算、信息截止、oracle 回放、简化日前双结算 | 辅助服务与规则一致性仍在最小实验阶段 |

两个相关仓库属于同一开发者，但都属于需要承认的相关工作。ERCOT 也曾公开 RTC+B Simulator 工具；未完成覆盖审查时不能声称不存在官方或其他仿真器。

差异必须通过证据建立：规则可追溯、事件时间明确、策略/oracle/执行共用可行域、真实样本可复现。增加 wrapper、更多日期或修复别人的导入错误，不足以单独支持独立研究贡献。

完整审查见 [项目对比](review/2026-10-26-RTCB-comparison.md)。

## 6. 已有探索结果必须保留

设置：100 MW / 200 MWh，RTE 85%，$2/MWh 退化成本，面板起止 SoC=50%，一小时 MPC，过去一天价格预测，假设价格在区间结束后再延迟五分钟可见。

| Central 日期 | 0.25h 规划请求在 1h 模型中被裁剪 | 占全部时段 | 0.25h→1h oracle 收益下降 |
|---|---:|---:|---:|
| 2026-02-02 至 02-04 | 154/864 | 17.82% | 0.0233% |
| 2026-01-24 至 01-26 | 157/864 | 18.17% | 0.4081% |

- 0.25h 是相关实现参数的敏感性检查，**不是历史 pre-RTC+B ECRS 规则**。
- 约 18% 的时段出现不可按该一小时模型执行的 reserve 请求，支持保留共同可行性校验。
- 总 oracle 收益差距只有约 0.02% 和 0.41%，目前经济影响证据偏弱。
- 一小时规划的 MPC 并未获得更高收益；两个版本在压力面板均亏损。不能据此宣传“正确规则带来更高策略收益”。
- 公开镜像的 2026 年 3 月 ECRS 列缺失约 35.4%。本次面板及历史无空值和网格缺口，但没有独立核对原始 ERCOT 数据或实际发布延迟。
- 两组运行是探索，不是独立留出验证，也不构成对另外两个仓库所有历史结果的重算。

完整结果、数值和范围见 [首轮验证报告](review/2026-10-26-ECRS-gate.md)。后续发现不应抹去这些不利结果。

## 7. 后续工作按验证关卡推进

### G1 — 规则与决策任务核对（当前主任务）

产物：规则清单、简明数学模型、信息/执行/结算时间线。

每条规则记录官方出处、条款/版本、生效日期、代码约束、测试案例及尚存解释。区分已生效规则、待实施文字、模型简化和数据假设。

通过条件：关键联合库存、功率和持续时间定义可以逐条核对；无法核实的部分收窄并明确标记，不能用经验公式替代后继续声称完整一致。

### G2 — 原始数据和可见性审核

从云服务器取得原始与处理后五分钟价格、时间戳含义、下载记录、缺口/修订报告和文件哈希；能量 SPP 另存供结算核对。

通过条件：确认粒度、主键、单位、时区、覆盖、重复、缺失和修订版本；不能静默补零、插值或用最近时间戳拼接。实际发布时间不可得时，以显式延迟假设做敏感性检查，不把假设写成已确认事实。

导出要求见 [给云服务器的请求](docs/request_ercot_gate_data_zh.md)。

### G3 — 统一内核与可达 oracle

在 G1/G2 明确的范围内，让策略接口、执行裁剪、物理变化、收益账本和 oracle 对齐。先核对一个 AS 产品，之后才判断是否扩展。

通过条件：边界案例、未来数据扰动、跨日库存、负价格互斥、终端条件、未发布信息和 oracle 回放全部通过；保存容差与求解状态。真实原始轨迹可用时，另做执行和账本对账。

现有 171 项测试属于这个方向的基础，不视为 G1/G2 或真实市场验证自动通过。

### G4 — 新固定窗口上的影响实验

在看新实验结果之前记录窗口、方法、参数、主要指标、排除规则、数据/规则版本和继续门槛。已用于调参或选择方法的日期保留访问记录，不重新称为 untouched test。

至少区分普通、稀缺和高波动窗口。比较时保持电池、价格、信息集、SoC 边界和账本一致，仅改变待检验的简化。先使用可解释的规则策略和可靠优化基线，不要求发明新算法。

主要指标：

1. 不可交付请求的频率、幅度和持续性，单独报告裁剪前后。
2. 合法执行后的净收益、风险与退化成本。
3. 约束修正是否改变方法排名或实际决策选择。
4. oracle 差距及其分母；负收益、零收益和失效情形不隐藏。
5. 差异是否由单个极端日驱动，以及跨窗口、hub、电池时长的稳定性。

数值意义门槛在实验协议中预先选择并解释；不能根据当前两组已知结果倒推一个刚好通过的标准。配对差异和时间依赖的分析必须保留原始日级/轨迹级证据。

### G5 — 根据结果决定交付规模

- 若核对后的机制在真实样本中反复导致不可交付承诺、实质收益偏差或决策排序变化，而且共同环境容易复现，则扩展成可发布 benchmark。
- 若主要增量仍是封装、更多价格日期或软件修补，而影响很小，则保留小工具、规则审计或向现有项目贡献。
- 若数据、关键规则或可见性无法核实，则停在受限模型；不升级为“完整市场仿真器”。

暂停的扩展：其他 AS 产品、情景生成、风险层、TFT、大型 RL、LLM agent、多市场和价格影响。仅在前述证据说明有必要时重新立项，不沿原版本表自动推进。

## 8. 复现与交付约定

- 保存数据文件哈希、下载/修订版本、规则版本、软件环境、代码哈希和时间窗口。
- 配置、协议和输入先固定，再运行结果。探索与确认性实验分开标记。
- 固定随机种子；跨求解器/平台按声明的数值容差核对，不承诺无条件逐比特一致。
- 新策略接入统一 evaluator，避免训练、优化和报告各自维护一套规则。
- 原始数据与镜像保留在 `data/raw/`，不因为本地可用就视为可重新发布；沿用数据来源归属说明。
- 发布版本、推送 GitHub 或提交 PR 另行明确；本蓝图本身不触发远端操作。
